# iPhone feature research: Wispr Flow → LocalScribe

Research checked 5 October 2026 UTC / 4 October in Los Angeles. This is a recommendation and evidence record, not a claim that the proposed features are implemented or physically verified. Current implementation and delivery status belong in [tasklist.md](../tasklist.md).

Scope: useful iPhone dictation behavior that can run locally through the already approved speech runtime and ordinary Swift/iOS APIs. Devesh explicitly deferred Transforms and other additional AI models. Accounts, cloud synchronization, automatic learning, team administration and subscription behavior are not requirements for this local app.

## Implemented update

LocalScribe 0.2.0 adds the P0 dictionary/snippet workflows, local Notes, history actions/export/retention, keyboard Cancel/Copy, idle-session choices, built-in microphone preference and optional recording haptics. Its recording preview is preserved. Changes use the existing runtime and native frameworks. Detailed results and physical verification limits are in [tasklist.md](../tasklist.md); the recommendation table below records the pre-change audit, not a claim of full parity. Cloud/account/team services, additional-model features, automatic learning, audio replay and host-context-dependent Undo remain excluded or deferred. Interaction sounds, additional home/control widgets and external import remain future improvements rather than implemented controls.

## Prioritized recommendations

P0 means the immediate personalization request; P1 means useful, small additions to the existing dictation workflow; P2 means broader native functionality after those paths work. All implementation decisions below are proposals.

| Priority / feature | Verified Wispr iPhone behavior | Recommendation for LocalScribe without another AI model |
|---|---|---|
| P0 — Dictionary corrections | Dictionary accepts a desired word/phrase. An optional correction maps recurring incorrect output to the intended spelling, capitalization and punctuation. iOS provides add, tap-to-edit and confirmed deletion; fields allow 59 characters after trimming. Its exact runtime matching rules are not documented. [Dictionary guide](https://docs.wisprflow.ai/articles/4052411709-Teach-Flow-your-words-with-the-dictionary) | Give corrections their own searchable list and clear **Recognized phrase → Replacement** editor. Add, edit, cancel and confirmed delete must preserve the prior item on failed saves. Use deterministic whole-phrase matching, Unicode letter/number boundaries, ignored casing, longest matching phrase first and one nonrecursive pass. Explain that this fixes recognized text, rather than promising acoustic recognition of an unrecognized name. |
| P0 — Snippets | A spoken trigger can expand alone or inside a sentence. The iOS Snippets tab provides +, trigger/expansion fields, tap-to-edit, long-press Copy and confirmed swipe/long-press Delete. Trigger length is under 60 characters; the mobile expansion has no stated character cap. [Snippet guide](https://docs.wisprflow.ai/articles/5784437944-create-and-use-snippets) | Add a distinct searchable **Snippets** list for email signatures, addresses and repeat replies. Save the expansion as literal text, preserving capitalization and internal line breaks. Share the deterministic matcher with corrections, reject ambiguous duplicate triggers, and never recursively expand inserted text. Prefer an explicit collision error over silently changing an existing correction. |
| P1 — History and recovery | Home groups history by date. Successful rows can be copied; failed entries can retry saved audio. Swipe/long-press actions support deletion. iPhone audio download is unavailable. [Navigation](https://docs.wisprflow.ai/articles/5096240724-navigating-the-wispr-flow-app-desktop-ios-and-android), [accuracy troubleshooting](https://docs.wisprflow.ai/articles/6901148133-Transcription-suddenly-got-worse-or-feels-less-accurate) | Keep editable history and add convenient row Copy/Share/Delete, search, date grouping and selection for local export. Preserve partial text after interruptions. Do not show Retry when PCM has been discarded; an audio-retention feature would change the current storage design and needs a separate decision. |
| P1 — Retention and export | iOS auto-delete is off by default; enabled, it retains the current calendar day's transcripts and clears older entries on sign-in/foreground entry. This differs from desktop's rolling 24-hour option. iOS has no delete-all control and bulk data export requires support. [Deletion](https://docs.wisprflow.ai/articles/4465314211-Delete-transcripts-and-history-in-Wispr-Flow), [data export](https://docs.wisprflow.ai/articles/8254696706-data-requests-get-a-copy-of-your-data-or-ask-us-to-delete-it) | Offer clearly named local retention choices, local JSON/text export through Files/Share, and confirmed deletion of selected/all history. Changing whether future history is saved must not silently erase existing entries. Dictionary/snippet export should use a separate, versioned schema and preview duplicate resolution before importing. These native controls improve local ownership without an account. |
| P1 — Recording versus idle session | A single Flow dictation has a five-minute cutoff. Separately, idle microphone-session timeout offers Never, one hour, 15 minutes, five minutes/default and Immediately. Its idle countdown does not interrupt active dictation. The microphone indicator and Live Activity are different states. [Mic/session guide](https://docs.wisprflow.ai/articles/3634682593-why-the-orange-dot-or-mic-indicator-stays-on-after-dictating-ios) | Retain bounded continuous dictation beyond two minutes; do not copy Flow's recording cutoff. Expose idle-session duration separately from elapsed recording time, with an explicit End microphone session action. Show recording, processing, ready and error consistently across app/keyboard/Live Activity; idle must not look like active speech capture. |
| P1 — Permission and handoff clarity | Full Access and microphone consent are separate. Flow sometimes returns to the host automatically, otherwise recording is already running when it shows manual swipe-back guidance. Its recording button finishes capture; during processing it cancels. [iOS handoff guide](https://docs.wisprflow.ai/articles/6269634092-adapting-to-ios-26-4) | Give specific permission status and next actions. Preserve a safe manual return path; do not claim generic automatic return to arbitrary apps. Keep Stop available during model preparation, retain text after cancelled/failed delivery and prevent overlapping dictations. Do not lock unrelated Dictionary/Snippets screens until first dictation. |
| P1 — Keyboard insertion and Undo | The Flow keyboard must remain visible for insertion. If delivery fails, history provides copy recovery. Its insertion Undo disappears after typing, cursor movement or a field change. [Insertion recovery](https://docs.wisprflow.ai/articles/7971211038-fix-text-not-pasting-after-dictation) | Keep document/context checks and insertion receipts. Add Undo only when the original document and unchanged inserted suffix can still be verified; otherwise offer Copy/Open transcript. A keyboard must not delete unrelated host text to simulate undo. Add an explicit “Add correction” route from a result only where both recognized and desired text are available. |
| P1 — Microphone route | iPhone has **Use Built-In Mic**, rather than the desktop device picker. Enabled, it records through the phone while headphones can remain connected; disabled, it allows the connected Bluetooth microphone. Calls/Siri/route changes may interrupt. [Microphone guide](https://docs.wisprflow.ai/articles/8884408990) | Show the actual current input and a built-in/system preference, applying changes to the next recording. Check the available input and verify it was selected rather than labeling a requested route as active. Keep interruption handling and visible recovery. |
| P1 — Feedback, permissions and accessibility | Flow separates interaction sounds, keyboard feedback, notifications and Live Activities. Live Activities show elapsed time; their permission row opens iOS settings. Its iOS controls announce state/action labels and follow Reduce Motion. [Notifications](https://docs.wisprflow.ai/articles/9454889914-how-to-disable-wispr-flow-notifications-on-ios), [accessibility](https://docs.wisprflow.ai/articles/3941699399-keyboard-and-screen-reader-accessibility-in-wispr-flow) | Add optional start/stop haptics and interaction sounds, keeping ordinary typing feedback separate. Use native accessible labels, Dynamic Type, reduced motion and light/dark colors. Notifications should be limited to useful saved-result/error recovery if permission is granted; no rating/referral/milestone prompts are necessary. |
| P2 — Local notes | Scratchpad supports voice/text notes, search, date grouping, editing/autosave, Copy/Share/Delete and native capture entry points. Notes and history have different purposes. Its Copy/Share exports raw Markdown; a notes dictation finishes before text appears. [iOS Notes](https://docs.wisprflow.ai/articles/3529886556-using-notes-in-wispr-flow-for-ios) | Reuse the local transcript editor/storage boundaries for named, editable notes and plain-text/Markdown sharing. Offer Save as note explicitly; keep history retention independent. Auto-titles can use the first nonempty line deterministically. Summaries, generated titles and cloud sync are deferred. |
| P2 — Shortcuts and system entry points | Flow documents clipboard/notes actions, Toggle, a recording Control Center control and a Notes Lock Screen widget. Destination differs when its keyboard is active. Live Activities offer recording actions. [Shortcuts](https://docs.wisprflow.ai/articles/1986921789-how-to-set-up-flow-shortcuts-for-iphone) | Extend the existing Action Button work with explicit destination actions rather than hidden destination changes. Add native control/widget entry points using current public iOS APIs. Keep physical start/stop, lock/background and result delivery verification separate from build/shortcut discovery. CPU-only Realtime and foreground ANE profiles need different lifecycle handling. |
| P2 — Language selection | iOS has a searchable language sheet, Auto-detect and immediate persistence; regional options affect spelling/script. Wispr's broad language support comes from its service, not from the picker. [Languages](https://docs.wisprflow.ai/articles/3191899797) | Expose only capabilities of the selected installed speech model. Realtime/Phonon are English-only; a multilingual profile can expose its own supported languages. A picker cannot create ASR language support, translation, Hinglish transcription or regional spelling behavior. Do not promise such behavior without runtime support and measured output. |

## Matching and integration decisions

Recommend **literal matching as the first supported contract**, with saved triggers shown plainly and a short example in each editor. Public iOS documentation does not settle fuzzy matching, punctuation-insensitive trigger normalization, conflict precedence or dynamic variables. The published whole-word/longest-phrase correction rules and liberal whole-trigger snippet matching are labeled **desktop**; they cannot establish iPhone behavior. Fuzzy expansion can insert an address or long reply when the speaker intended ordinary text, so it is not justified by a parity label. [Dictionary behavior](https://docs.wisprflow.ai/articles/4052411709-Teach-Flow-your-words-with-the-dictionary), [snippet behavior](https://docs.wisprflow.ai/articles/5784437944-create-and-use-snippets).

At the start of this research, code inspection found `DictionaryRule`, a one-pass longest-first whole-phrase `TranscriptCorrection` matcher and protected `DictionaryStore`/`HistoryStore` in [Models.swift](../Sources/LocalScribeCore/Models.swift) and [HistoryStore.swift](../Sources/LocalScribeCore/HistoryStore.swift). This is a baseline observation, not verification of subsequent parity changes. Reuse these boundaries instead of adding a model or framework for replacements. Build snippet spans and correction spans against the original recognized text, resolve overlaps deterministically, and apply once; separate chained passes could rewrite a user's saved expansion. Preserve raw recognition separately from transformed display where editing/diagnostics require it.

Do not infer punctuation, grammar cleanup, filler removal, self-correction, tone adjustment, translation or semantic voice-edit commands from deterministic replacements. Existing ASR punctuation may remain model-specific. Wispr's Style/Polish/Transforms are model-backed functionality and explicitly outside the present direction. [Transforms guide](https://docs.wisprflow.ai/articles/8068950331-how-to-use-transforms-beta).

## Verification required before delivery claims

- Unit tests for Unicode boundaries, apostrophes, overlapping triggers, case variants, duplicate conflicts, literal dollar/backslash text, multiline expansions and no recursive replacement. Check both models and shared app/keyboard/shortcut results.
- Storage tests for failed add/edit/delete, preserved originals, migration of existing dictionary/history, retention boundaries and export/import round trips without unintended deletion.
- Real microphone-to-model checks for distinctive triggers, ordinary sentences, repeated triggers, final partial windows and interruption/cancellation. Changing the personalization pipeline must not change recording resource bounds.
- Actual host keyboard checks for insertion, selection replacement, unchanged-context Undo, cursor movement, host switches, clipboard recovery and unavailable permissions. Shortcuts/widgets require Devesh's physical replay under the current phone-control arrangement.

No feature implementation, dependency installation, Git operation, account action or phone interaction was performed as part of this research record.
