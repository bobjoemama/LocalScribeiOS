# Metrics collector dependency review

The Mac collector uses GPL-3.0-or-later pymobiledevice3 11.23.0 (license retained locally), pinned to its upstream release commit `114671735f19ae4310c2aec6fb0d954f5295c04a`. The project has about 2,800 stars and active releases. That is a maintenance/provenance signal, not proof of safety. Apple's public SDK supplies the iPhone measurements and Network transport without adding third-party iPhone packages.

The reviewed runtime contains 101 applicable packages on macOS arm64/Python 3.13. The exact target lock and [machine-readable review](dependency-review.json) record versions and artifact hashes. Advisory checks found no known vulnerabilities on 6 October 2026. All downloaded upstream wheels matched locked/PyPI SHA-256 hashes and their RECORD digests. Thirteen packages contain binaries; one ships Windows-only DLLs. Native binaries were identified and verified by hash, not fully reverse-engineered.

One dependency, hexdump 3.3, has no official wheel. Its locked source archive was hash-verified; every Python/build file was read, and a local universal wheel was built with already-installed setuptools/wheel without network activity. Its module matched the reviewed source. The local wheel hash is recorded in the target lock. Recreating an environment requires that reviewed wheel; a stock install must not silently permit arbitrary source builds. The wheelhouse is local generated output, outside Git. Universal upstream resolutions remain in `uv.lock`/`requirements.lock`; platform installation used only the audited local wheelhouse, exact hashes, no index and no source builds.

Reviewed upstream paths were UserspaceRsdTunnel, the USB mux socket/device selection, DvtProvider, DeviceInfo, Sysmontap, Graphics and their sampling/context cleanup. The collector selects an explicit USB phone on the local `/var/run/usbmuxd` socket, disables auto-pairing and remote/native fallback, requests minimal attributes, and sends only normalized numeric counters for its authenticated app PID. It never invokes app launch, restore, file transfer, developer-image installation, administrator elevation or automatic update APIs. Default in-process tunnel transport uses a private Unix relay, with upstream loopback-only fallback; nothing is advertised on the LAN.

The environment starts with a small explicit set of variables, clearing `COLOREDLOGS_AUTO_INSTALL` before Python starts. This neutralizes the reviewed optional logging startup hook. Pairing codes use stdin and are not written to logs, command arguments or settings. Direct developer probes print allowlisted capability names only. Trace exports use Apple's fixed installed xctrace executable and local temporary files; recording and sharing require the user's actions.

The signed Mac GUI references this checkout's audited collector and isolated environment, so it is a local installation. Move the checkout only after rebuilding its paths. There is no installed daemon or automatic startup. Stop/Quit terminates the owned child, and context teardown retires developer sampling. Apple Instruments sessions started independently remain the user's processes.

This is a bounded review. Hashes, popularity and a clean advisory scan cannot establish that all code is harmless. The integration reduces the permissions and operations used, preserves errors and unknown values, and adds tests for protocol, cancellation and stale-state behavior.
